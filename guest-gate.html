P14 · 游客访问控制

原则：游客可阅读、不可提交、不可下载。受限功能触发时，弹窗引导登录 / 注册。

📋 权限矩阵

功能 游客 登录学生 说明
浏览内容（工具 / 真题列表 / 帖子） ✓ 可用 ✓ 纯阅读，含学校切换、全站搜索
纯计算类小工具（空教室查询 / 绩点计算器） ✓ 可用 ✓ 不产生数据提交，开放使用
⬇ 下载真题文件 ✗ 拦截 ✓ 场景 A 弹窗
✨ AI 问答（真题库提问） ✗ 拦截 ✓ 场景 B 弹窗；控制 API 成本
💬 社区发帖 / 回帖 / 点赞 / 收藏 ✗ 拦截 ✓ 场景 C；按钮呈"锁定态"
⬆ 上传真题 ✗ 拦截 ✓ 点击后跳登录，回跳保留表单
🤝 竞赛寻搭子（提交信息） ✗ 拦截 ✓ 同上
🚨 纠错反馈（企微导航 / 帖子举报） ✗ 拦截 ✓ 同上
👤 个人中心 ✗ 需登录 ✓ 直接跳登录页

💡 判定规则一句话："只读的都开放，要写入服务端的都拦截。"纯前端计算（绩点、空教室）无需登录。

场景 C · 社区「＋ 发帖」按钮的游客锁定态

＋ 发帖 （登录后） 🔒 登录后发帖 （游客态）

点击锁定态按钮 → 弹右侧同款弹窗

通用弹窗规范（所有场景复用）

  • 遮罩：半透明黑 45%，弹窗居中
  • 图标：与被拦功能一致（📄/✨/💬…）
  • 标题：「×× 需要登录」/「×× 面向登录用户开放」
  • 说明：一句话价值 + 一句话降低门槛（"注册只需 1 分钟"）
  • 按钮：登录（主） + 注册（次）
  • 次操作："暂不登录，先逛逛" 可关闭，不强制
  • 回跳：登录成功后回到触发页并保留上下文（如已填的表单）
  • 提示条替代：上传页等整页受限场景，用页内黄色提示条 + 登录按钮，不用弹窗

📌 设计与开发约定

  • 所有前台页面导航在游客态显示「注册 + 登录」（见首页），登录态显示头像昵称（见个人中心）；无需为每页单独设计游客变体
  • 受限按钮的游客态统一用「🔒 + 灰底」样式（场景 C）
  • 拦截弹窗是全局唯一组件，文案按场景注入；开发时做成 <LoginGate feature="download"/> 一类可复用组件
