# 06 · 代码逐行讲解

> 这份文档是“导游”，不是 API 手册。建议一边打开源码一边看。
> 先读第 1 章的阅读顺序，再按文件跳转；每一段都先讲“它在链路里的位置”，再逐行讲。

## 1. 先建立一张地图

一次登录请求经过的十站：

```text
1 浏览器表单 submit
2 api.js：JSON + CSRF 头 + fetch
3 Nginx：/api/ 反代到 127.0.0.1:3100
4 Express：request id → 日志 → 安全头 → JSON → Cookie → CSRF
5 路由：zod 校验参数
6 service：查数据库
7 scrypt：验密码
8 session：regenerate + 写 user_sessions + Set-Cookie
9 Express：返回 JSON
10 前端：取 data/error.code，跳转或提示
```

任何一站失败，后面的站都不会执行。读代码时始终问自己：**这一行在十站的哪一站？**

推荐阅读顺序：

1. `web/assets/js/api.js`：一次请求怎么发出去；
2. `server/src/app.js`：请求进来后按什么顺序过中间件；
3. `server/src/middleware/csrf.js`：为什么写请求需要令牌；
4. `server/src/middleware/session.js` + `mysql-session-store.js`：登录态存在哪；
5. `server/src/modules/auth/service.js` + `routes.js`：登录业务；
6. `server/src/modules/admin-auth/service.js`：密码 + TOTP 状态机；
7. `server/src/modules/exams/service.js`：文件上传事务与下载鉴权；
8. 前端页面模块：数据怎么渲染。

`type="module"` 有三个含义：

1. 浏览器把它当 ES Module 执行；
2. 模块内默认严格模式；

### 2.2 `api.js`：所有请求的唯一入口

文件路径：`web/assets/js/api.js`。

#### 2.2.1 顶部常量与 ApiError

```js
const SAFE_METHODS = new Set(['GET', 'HEAD', 'OPTIONS']);
// 只读方法集合。写方法才需要 CSRF。
let csrfToken = null;
// 浏览器内存里的 CSRF 令牌缓存；刷新页面就没了，需要重新取。
```

```js
export class ApiError extends Error {
  constructor(status, payload) {
    super(payload?.error?.message || '请求失败');
    // 调用父类 Error，message 优先用后端返回的中文文案。
    this.name = 'ApiError';                     // 方便调试时识别错误类型
    this.status = status;                       // HTTP 状态码，如 401/403/422
    this.code = payload?.error?.code || 'UNKNOWN'; // 业务错误码，如 USER_PENDING
    this.details = payload?.error?.details || null; // 字段级错误
    this.requestId = payload?.error?.requestId || ''; // 后端日志追踪 id
  }
}
```

为什么要有 `code`？因为仅凭 HTTP 状态码无法区分“未登录”“待审核”“被驳回”——它们都可能是 401/403。前端需要根据 `code` 显示不同的中文提示。

#### 2.2.2 读取响应

```js
async function readPayload(response) {
  const type = response.headers.get('content-type') || '';
  if (response.status === 204) return null;     // 204 没有响应体（如退出登录）
  if (type.includes('application/json')) {
    return response.json().catch(() => null);   // JSON 解析失败就返回 null，不让页面崩
  }
  return { rawText: await response.text() };    // 非 JSON（例如文件）先读文本
}
```

#### 2.2.3 获取 CSRF 令牌

```js
async function ensureCsrfToken() {
  if (csrfToken) return csrfToken;              // 已有缓存直接用
  const response = await fetch('/api/csrf', { credentials: 'same-origin' });
  // credentials: 'same-origin' 让浏览器带上同源 Cookie；
  // 这个请求还会让服务端下发 campus_csrf Cookie。
  const payload = await readPayload(response);
  if (!response.ok) throw new ApiError(response.status, payload);
  csrfToken = payload?.data?.token || null;     // 取出 token 存内存
  return csrfToken;
}
```

#### 2.2.4 核心 `request()`

```js
async function request(method, path, options = {}) {
  const { body, headers = {}, raw = false, retried = false } = options;
  // body：请求体；headers：额外头；raw：是否返回整包 {data,meta}；
  // retried：是否已经因 CSRF 过期重试过一次，避免无限重试。

  const finalHeaders = { Accept: 'application/json', ...headers };
  // 默认希望服务端返回 JSON，允许调用方覆盖。

  const init = {
    method,
    credentials: 'same-origin',                 // 同源请求自动带 Cookie
    headers: finalHeaders,
  };

  if (body !== undefined) {
    if (body instanceof FormData) {
      init.body = body;
      // FormData 不要手动设 Content-Type，浏览器会自动加 multipart boundary。
    } else {
      finalHeaders['Content-Type'] = 'application/json';
      init.body = JSON.stringify(body);         // 普通对象序列化成 JSON 字符串
    }
  }

  if (!SAFE_METHODS.has(method)) {
    finalHeaders['X-CSRF-Token'] = await ensureCsrfToken();
    // 写请求先确保有 CSRF 令牌，并放进请求头。
  }

  const response = await fetch(path, init);
  const payload = await readPayload(response);

  if (!response.ok) {
    if (response.status === 403
      && payload?.error?.code === 'CSRF_INVALID'
      && !retried) {
      csrfToken = null;                          // 缓存过期，清掉
      return request(method, path, { ...options, retried: true });
      // 重新取一次令牌，只重试一次。
    }

    if (response.status === 401) {
      window.dispatchEvent(new CustomEvent('api:unauthorized', {
        detail: { path },
      }));
      // 广播未登录事件，页面可以监听后跳登录页。
    }

    throw new ApiError(response.status, payload);
    // 统一抛 ApiError，页面只处理一种错误类型。
  }

  return raw ? payload : (payload?.data ?? payload);
  // raw=true 时列表页能拿到 meta；默认只返回 data，页面更简洁。
}
```

#### 2.2.5 `api.get/post/patch` 等薄封装

#### 2.2.6 上传：为什么用 XHR

```js
upload(path, formData, { onProgress } = {}) {
  return ensureCsrfToken().then((token) => new Promise((resolve, reject) => {
    const xhr = new XMLHttpRequest();
    xhr.open('POST', path, true);                // 异步 POST
    xhr.withCredentials = true;                  // 带 Cookie
    xhr.setRequestHeader('Accept', 'application/json');
    xhr.setRequestHeader('X-CSRF-Token', token); // 上传也是写请求

    xhr.upload.onprogress = (event) => {
      if (event.lengthComputable && typeof onProgress === 'function') {
        onProgress(Math.round((event.loaded / event.total) * 100));
        // fetch 没有标准的 upload.onprogress，所以上传改用 XHR。
      }
    };

    xhr.onload = () => {
      let payload = null;
      try { payload = JSON.parse(xhr.responseText); } catch { /* 文件响应等非 JSON */ }
      if (xhr.status >= 200 && xhr.status < 300) resolve(payload?.data ?? payload);
      else reject(new ApiError(xhr.status, payload));
    };
    xhr.onerror = () => reject(new ApiError(0, {
      error: { code: 'NETWORK_ERROR', message: '网络连接失败' },
    }));
    xhr.send(formData);
  }));
}
```

#### 2.2.7 下载：先检查鉴权，再触发浏览器保存

```js
async download(path, fallbackName = 'download') {
  const response = await fetch(path, { credentials: 'same-origin' });
  const type = response.headers.get('content-type') || '';
  if (!response.ok) {
    const payload = type.includes('application/json')
      ? await response.json().catch(() => null)
      : null;
    throw new ApiError(response.status, payload);
    // 如果未登录，服务端返回 JSON 401；先解析错误，不能把错误页当成文件下载。
  }

  const disposition = response.headers.get('content-disposition') || '';
  const utf8Match = disposition.match(/filename\*=UTF-8''([^;]+)/i);
  const simpleMatch = disposition.match(/filename="([^"]+)"/i);
  const filename = utf8Match ? decodeURIComponent(utf8Match[1])
    : (simpleMatch?.[1] || fallbackName);
  // 优先 RFC 5987 的 filename*，中文文件名用它。

  const blob = await response.blob();             // 文件变成 Blob
  const url = URL.createObjectURL(blob);          // 生成临时 URL
  const anchor = document.createElement('a');
  anchor.href = url;
  anchor.download = filename;                     // 触发下载
  document.body.appendChild(anchor);
  anchor.click();
  anchor.remove();
  setTimeout(() => URL.revokeObjectURL(url), 1000); // 释放内存
  return filename;
}
```

### 2.3 `auth.js`：登录态与学校切换

#### 2.3.1 为什么每次都问后端

```js
export async function getMe(force = false) {
  if (meCache && !force) return meCache;          // 当前页内缓存，减少重复请求
  try {
    const data = await api.get('/api/auth/me');
    meCache = data.user;
    return meCache;
  } catch (error) {
    if (error.status === 401 || error.status === 403) {
      meCache = null;
      return null;                                 // 未登录/待审核都当游客
    }
    throw error;
  }
}
```

前端**不在 localStorage 存用户信息或 token**。用户信息只存在当前页面内存，刷新后重新问后端。这样管理员禁用用户、改学校、改密码都能立即生效。

#### 2.3.2 `requireLogin`

```js
export async function requireLogin(next = location.pathname + location.search) {
  const me = await getMe();
  if (!me) {
    location.replace(`login.html?next=${encodeURIComponent(next)}`);
    // 记住用户原本想去的页面，登录后再回来。
    return null;
  }
  return me;
}
```

`safeNext()` 会限制 `next` 只能是站内相对路径，防止开放重定向：

```js
if (!next) return fallback;
if (!/^[A-Za-z0-9._/?=&%-]+$/.test(next)) return fallback;
if (next.startsWith('http') || next.startsWith('//')) return fallback;
```

### 2.4 `ui.js`：安全渲染

```js
export function el(tag, attrs = {}, ...children) {
  const node = document.createElement(tag);
  for (const [key, value] of Object.entries(attrs || {})) {
    if (value === null || value === undefined || value === false) continue;
    if (key === 'class') node.className = value;
    else if (key === 'dataset') Object.assign(node.dataset, value);
    else if (key === 'text') node.textContent = value;
    else if (key === 'html') node.innerHTML = value; // 只给可信模板用
    else if (key.startsWith('on') && typeof value === 'function') {
      node.addEventListener(key.slice(2).toLowerCase(), value);
    } else if (key in node) node[key] = value;
    else node.setAttribute(key, String(value));
  }
  appendChildren(node, children);
  return node;
}
```

关键点：

- 字符串 children 最终走 `document.createTextNode`，不是 `innerHTML`；
- 用户写的帖子标题哪怕包含 `<script>`，也只会显示成文本；
- 这是防御 XSS 最便宜、最可靠的办法。

`openDialog()` 用 DOM 创建弹窗，支持 `text/textarea/select` 字段，返回 Promise；`toast()` 在右下角显示提示；`errorText()` 把后端 `code` 映射成中文。

## 4. 安全中间件

### 4.1 `csrf.js` 逐行

```js
export const CSRF_COOKIE = 'campus_csrf';
const SAFE_METHODS = new Set(['GET', 'HEAD', 'OPTIONS']);

function cookieOptions() {
  return {
    httpOnly: false,        // 前端必须能读出来放进请求头
    sameSite: 'lax',        // 跨站写请求默认不带
    secure: config.isProd,  // 生产 HTTPS 才加 Secure
    path: '/',
    maxAge: 2 * 60 * 60 * 1000,
  };
}

export function issueCsrfToken(req, res) {
  const existing = req.cookies?.[CSRF_COOKIE];
  const token = typeof existing === 'string' && existing.length >= 20
    ? existing
    : randomToken(24);
  // 已有就复用，避免多个标签页互相覆盖。
  res.cookie(CSRF_COOKIE, token, cookieOptions());
  res.json({ data: { token } });
}

export function csrfProtection(req, res, next) {
  if (SAFE_METHODS.has(req.method)) return next();
  const cookieToken = req.cookies?.[CSRF_COOKIE];
  const headerToken = req.get('X-CSRF-Token');
  if (typeof cookieToken !== 'string'
    || typeof headerToken !== 'string'
    || !cookieToken || !headerToken
    || !safeEqual(cookieToken, headerToken)) {
    return next(new AppError(403, 'CSRF_INVALID', '页面令牌已过期，请刷新后重试'));
  }
  return next();
}
```

为什么不是 HttpOnly？因为前端需要读到它再放进请求头；真正的会话 Cookie 仍然是 HttpOnly。攻击者能跨站发请求，但**读不到你站点里的 Cookie，也拿不到请求头**。

### 4.2 `session.js` 与 MySQL Store

`session.js` 配置两套：

Store 的四个方法：

```js
get(sid, callback) {
  const hashedId = sha256Hex(sid);   // Cookie 里的原始 sid 只用于哈希
  pool.execute(
    `SELECT data FROM ${this.table}
      WHERE id = ? AND expires_at > UTC_TIMESTAMP(3) LIMIT 1`,
    [hashedId],
  ).then(([rows]) => {
    if (!rows.length) return callback(null, null);
    const raw = rows[0].data;
    const data = typeof raw === 'string' ? JSON.parse(raw) : raw;
    return callback(null, data);
  }).catch(callback);
}
```

```js
set(sid, sessionData, callback) {
  const hashedId = sha256Hex(sid);
  const actorId = sessionData[this.sessionKey];
  // sessionKey 是 userId/adminId，数据库列是 user_id/admin_id。
  if (!actorId) return callback(null);  // 没有用户的空会话不存
  const expiresAt = sessionData.cookie?.expires
    ? new Date(sessionData.cookie.expires)
    : new Date(Date.now() + this.defaultTtlMs);
  const json = JSON.stringify(sessionData);
  pool.execute(
    `INSERT INTO ${this.table} (id, ${this.idField}, data, expires_at, last_seen_at)
     VALUES (?, ?, ?, ?, UTC_TIMESTAMP(3))
     ON DUPLICATE KEY UPDATE data = ?, expires_at = ?, last_seen_at = UTC_TIMESTAMP(3)`,
    [hashedId, actorId, json, expiresAt, json, expiresAt],
  ).then(() => callback(null)).catch(callback);
}
```

- 这里必须区分“会话里的字段名”和“数据库列名”，否则会出现“登录成功但刷新掉线”的问题；
- `touch` 更新过期时间；
- `destroy` 删除会话；
- `cleanupExpiredSessions` 由 server.js 每小时调用。

## 9. TOTP 算法逐行

文件：`server/src/utils/crypto.js`。

### 9.1 Base32

```js
const BASE32_ALPHABET = 'ABCDEFGHIJKLMNOPQRSTUVWXYZ234567';
// TOTP 密钥标准编码，腾讯身份验证器也按这个解析。

export function base32Encode(buffer) {
  let bits = 0;
  let value = 0;
  let output = '';
  for (const byte of buffer) {          // 每次读 8 位
    value = (value << 8) | byte;
    bits += 8;
    while (bits >= 5) {                 // Base32 每 5 位一个字符
      output += BASE32_ALPHABET[(value >>> (bits - 5)) & 31];
      bits -= 5;
    }
  }
  if (bits > 0) output += BASE32_ALPHABET[(value << (5 - bits)) & 31];
  return output;
}
```

解码是反向过程：每个字符查表得到 0–31，拼回比特流，再每 8 位取一个字节。

### 9.2 生成动态码

```js
export function generateTotp(secretBase32, { timestamp = Date.now(), digits = 6, period = 30 } = {}) {
  const counter = totpStep(timestamp, period);
  // 时间步 = floor(Unix 秒 / 30)，每 30 秒加一。

  const counterBuffer = Buffer.alloc(8);
  counterBuffer.writeBigUInt64BE(BigInt(counter));
  // RFC 4226：把时间步写成 8 字节大端整数。

  const hmac = crypto.createHmac('sha1', base32Decode(secretBase32))
    .update(counterBuffer)
    .digest();
  // HMAC-SHA1(密钥, 时间步)。

  const offset = hmac[hmac.length - 1] & 0x0f;
  // 动态截断：用最后一个字节的低 4 位决定从哪取 4 字节。

  const binary = ((hmac[offset] & 0x7f) << 24)
    | ((hmac[offset + 1] & 0xff) << 16)
    | ((hmac[offset + 2] & 0xff) << 8)
    | (hmac[offset + 3] & 0xff);
  // 取 4 字节，最高位清零，避免负数。

  return String(binary % 10 ** digits).padStart(digits, '0');
  // 取模得到 6 位数字，不足补 0。
}
```

### 9.3 验证动态码

```js
export function verifyTotp(secretBase32, code, { timestamp = Date.now(), window = 1, period = 30 } = {}) {
  const normalized = String(code ?? '').trim();
  if (!/^\d{6}$/.test(normalized)) return { valid: false, step: null };

  const currentStep = totpStep(timestamp, period);
  for (let offset = -window; offset <= window; offset += 1) {
    const step = currentStep + offset;                 // 当前、前 30 秒、后 30 秒
    const expected = generateTotp(secretBase32, { timestamp: step * period * 1000, period });
    if (safeEqual(expected, normalized)) return { valid: true, step };
    // 恒定时间比较，避免根据耗时猜数字。
  }
  return { valid: false, step: null };
}
```

`window=1` 是为了容忍手机与服务器几十秒的时钟偏差。

```sql
-- 学号只在同校唯一；不同学校可以有相同学号。

UNIQUE KEY uq_users_id_school (id, school_id),
-- 组合外键的引用目标：让 (user_id, school_id) 可以指向 users。

KEY idx_users_school_status (school_id, status, created_at),
-- 后台按学校+状态筛选，按时间排序。

CONSTRAINT fk_users_school FOREIGN KEY (school_id) REFERENCES schools(id)
-- 学校必须存在。
```

`exams` 的组合外键：

```sql
CONSTRAINT fk_exams_uploader FOREIGN KEY (uploader_id, school_id)
  REFERENCES users(id, school_id)
-- 上传者必须属于同一所学校。
```

软删除：

```sql
status ENUM('published','hidden','deleted')
-- 删除帖子不真的 DELETE，保留审计和恢复能力。
```

## 12. 测试怎么读

- 单元测试只测纯函数：TOTP RFC 向量、scrypt 哈希、AES 篡改、序列化；
- 集成测试用 `supertest.agent(app)` 保持 Cookie，`getCsrf()` 拿令牌；
- 每个测试文件 `before` 清空 `campus2_test`，`after` `pool.end()`；
- 断言“状态码 + `error.code` + 关键字段”，不断言整段 JSON；
- 浏览器冒烟用真实 Edge/Chrome 打开页面，收集 JS 异常与请求失败。

## 13. 自己改一个功能（练习路线）

### 练习 A：给帖子加评论

### 练习 B：增加一名修复的纠错通知

### 练习 C：把规则问答换成真实模型
