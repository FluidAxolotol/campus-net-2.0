# 05 · 部署与运行

## 1. 运行方式一览

| 方式 | 适用 | 入口 | 需要的组件 |
|---|---|---|---|
| Docker Compose 全栈 | 最快看到完整链路 | <http://localhost:8088> | Docker Desktop |
| 本机 Node + Docker MySQL | 开发调试 | <http://127.0.0.1:3100> | Node 24、Docker、可选 Nginx |
| 单机生产 | 云服务器 | https://域名 | Node 24、Nginx、MySQL 8、systemd |

## 2. 一键全栈（Docker）

### 2.1 启动

```bash
cd campus-net-2.0
docker compose up --build
```

首次会拉取 MySQL 8 与 Nginx 镜像、构建 Node 镜像，耗时取决于网络。
API 容器启动命令是：

```sh
npm run migrate && npm run seed && npm start
```

`seed` 幂等，重复启动不会重复插数据。

### 2.2 访问

<http://localhost:8088/>

- 静态页与 `/api` 都经过 Nginx；
- MySQL 宿主机端口 3308，方便用客户端查看；
- 上传文件挂载在 `server/uploads`。

### 2.3 停止 / 重置

```bash
docker compose down          # 停止，保留数据
docker compose down -v       # 停止并清空 MySQL 数据卷
```

### 2.4 查看状态与日志

```bash
docker compose ps
docker compose logs -f api
docker compose logs -f nginx
docker exec -it campus2-mysql mysql -ucampus2 -pcampus2_pass campus2
```

### 2.5 Docker 常见问题

| 现象 | 处理 |
|---|---|
| `cannot connect to Docker daemon` | 先启动 Docker Desktop，等引擎就绪 |
| API 容器反复重启 | `docker compose logs api`，多半是数据库未就绪或迁移失败 |
| 8088 被占用 | 修改 `docker-compose.yml` 的 `"8088:80"` 左侧端口 |
| 想重新演示首次管理员绑定 | `docker compose down -v` 后重新启动 |

## 3. 本机开发

### 3.1 只启动 MySQL

```bash
docker compose up -d mysql
```

MySQL 在宿主机 `127.0.0.1:3308`，账号 `campus2 / campus2_pass`，库 `campus2`。

### 3.2 配置并启动 API

```bash
cd server
cp .env.example .env
# 按需修改 .env；开发环境可以使用示例密钥
npm install
npm run migrate
npm run seed
npm run dev
```

- `npm run dev` 使用 `node --watch`，改文件自动重启；
- 访问 <http://127.0.0.1:3100/>，开发环境由 Express 的 `express.static` 兜底；
- 此时没有经过 Nginx；要验证反代，用 Docker 启动 Nginx 服务，或使用本机 Nginx。

### 3.3 创建测试库

集成测试需要 `campus2_test`：

```bash
docker exec campus2-mysql mysql -uroot -proot_pass_change_me -e "
CREATE DATABASE IF NOT EXISTS campus2_test
  CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
GRANT ALL PRIVILEGES ON campus2_test.* TO 'campus2'@'%';
FLUSH PRIVILEGES;"
```

### 3.4 本机 Nginx（可选）

`deploy/nginx/campus2.local.conf` 是完整 nginx 配置：

1. 把 `root` 改成你本机仓库的 `web/` 绝对路径；
2. 启动：`nginx -c /绝对路径/campus2.local.conf`；
3. 访问 <http://localhost:8088>；
4. 日志在 `/tmp/campus2-nginx-access.log` 与 `error.log`。

Windows 用户建议直接用 Docker 的 Nginx 服务，避免路径差异。

## 4. 环境变量

见 [`server/.env.example`](../server/.env.example)。

| 变量 | 作用 | 生产注意 |
|---|---|---|
| `NODE_ENV` | 开关：trust proxy / Secure Cookie / 静态兜底 | 必须 `production` |
| `PORT` | Express 监听端口 | 与 Nginx `proxy_pass` 一致 |
| `PUBLIC_ORIGIN` | 对外地址 | 与真实域名一致 |
| `DB_*` | MySQL 连接 | 最小权限账号，密码只在 `.env` |
| `SESSION_SECRET` | 学生会话签名 | 生产必须随机长字符串 |
| `ADMIN_SESSION_SECRET` | 管理员会话签名 | 必须与上者不同 |
| `TOTP_ENCRYPTION_KEY` | AES-256-GCM 密钥 | 64 位 hex；丢失需重新绑定所有管理员 |
| `ADMIN_USERNAME` / `ADMIN_DEFAULT_PASSWORD` | 首次 seed 管理员 | 首次登录会强制改密；生产不要长期保留默认密码 |
| `UPLOAD_DIR` | 上传目录 | 必须在 `web/` 之外 |
| `USE_X_ACCEL` | 下载方式 | 生产 `true`，并与 Nginx `/__files/` 成对 |
| `RATE_LIMIT_DISABLED` | 限流开关 | 生产必须 0/不设 |

生成密钥：

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

## 5. Nginx 的三个核心 location

```nginx
location /assets/ { ... }   # 静态资源直出
location /api/ { proxy_pass http://127.0.0.1:3100; ... }
location /__files/ { internal; alias /srv/campus2.0/shared/uploads/; }
```

- 静态：`root` 指向 `web/`，`try_files` 找不到就 404；
- API：Node 只监听 127.0.0.1，公网只能看到 Nginx；
- 文件：`internal` 让外部直接访问返回 404，只能由 Express 鉴权后 `X-Accel-Redirect` 命中；
- 代理头：`Host`、`X-Real-IP`、`X-Forwarded-For`、`X-Forwarded-Proto`、`X-Request-Id`；
- 生产 HTTPS：80 → 301；443 配证书、HSTS、TLS 版本；
- `client_max_body_size 21m`：20MB 真题 + multipart 余量。

## 6. 单机生产发布

### 6.1 目录

```text
/srv/campus2.0/
├── releases/
│   └── 20261120-170000/
├── current -> releases/20261120-170000
├── shared/uploads/
├── logs/
├── backups/
└── .env
```

### 6.2 发布步骤

```bash
# 0. 本地或构建机
cd campus-net-2.0
./deploy/scripts/release.sh 20261120-170000
# 生成 dist/campus2.0-20261120-170000.tar.gz + .sha256

# 1. 上传到服务器
scp dist/campus2.0-*.tar.gz* user@server:/srv/campus2.0/releases/

# 2. 服务器：解压
cd /srv/campus2.0/releases
tar -xzf campus2.0-20261120-170000.tar.gz
sha256sum -c campus2.0-20261120-170000.tar.gz.sha256

# 3. 切软链
ln -sfn /srv/campus2.0/releases/campus2.0-20261120-170000 /srv/campus2.0/current

# 4. 安装生产依赖并迁移
cd /srv/campus2.0/current/server
npm ci --omit=dev
npm run migrate

# 5. 重启
sudo systemctl restart campus-api

# 6. 健康检查
./deploy/scripts/healthcheck.sh https://campus.example.com
```

回滚：把 `current` 软链指回上一个 release，再 `systemctl restart campus-api`。

### 6.3 systemd

```bash
sudo cp deploy/systemd/campus-api.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now campus-api
sudo systemctl status campus-api
sudo journalctl -u campus-api -f
```

关键点：

- `ExecStart` 直接 `/usr/bin/node src/server.js`，不经过 npm；
- `EnvironmentFile=/srv/campus2.0/.env`，密钥不在发布目录里；
- `Restart=always` + `RestartSec=3`；
- `ProtectSystem=full`、`ProtectHome=true`、`ReadWritePaths` 只放开 uploads 与 logs。

### 6.4 备份

开发环境：

```bash
CAMPUS_ROOT="$PWD" \
ENV_FILE="$PWD/server/.env" \
BACKUP_DIR="$PWD/backups" \
./deploy/scripts/backup.sh
```

生产：

```bash
CAMPUS_ROOT=/srv/campus2.0 /srv/campus2.0/current/deploy/scripts/backup.sh
```

cron 每日 02:30：

```cron
30 2 * * * CAMPUS_ROOT=/srv/campus2.0 /srv/campus2.0/current/deploy/scripts/backup.sh >> /srv/campus2.0/logs/backup.log 2>&1
```

数据库和 uploads 必须一起备份；备份后必须恢复到临时库演练一次。

## 7. 验证清单

### 7.1 基础

- [ ] `GET /api/health` 返回 `status=ok, db=ok`
- [ ] 首页、登录页静态资源 200
- [ ] `/api` 经 Nginx 返回 JSON，不直接暴露 3100
- [ ] `/__files/xxx` 直接访问 404（生产 internal 生效）

### 7.2 用户链路

- [ ] 注册 → 管理员看到 pending → 登录 403 `USER_PENDING`
- [ ] 审核通过 → 学生登录 200
- [ ] 学生只能看本校数据；改 URL `schoolId` 无效；跨校 404
- [ ] 上传 PDF → 管理员通过 → 学生下载
- [ ] 上传伪造 `.pdf` → 422
- [ ] 发帖、点赞、问答正常
- [ ] 退出后 `/api/auth/me` 401

### 7.3 管理员链路

- [ ] 首次登录 → 改密 + 扫码绑定 → 显示恢复码
- [ ] 再次登录 → 密码 + 动态码
- [ ] 同一动态码第二次使用 → 401 `TOTP_REPLAY`
- [ ] 切换学校后数据变化
- [ ] 停用学生后，其会话立即失效
- [ ] 审计日志出现对应记录

### 7.4 安全

- [ ] 写请求缺少 `X-CSRF-Token` → 403 `CSRF_INVALID`
- [ ] `campus_sid` 用户 Cookie 访问 `/api/admin/*` → 401
- [ ] 生产 Cookie 带 `Secure`、`HttpOnly`、`SameSite=Lax`
- [ ] HTTPS 与 HSTS 生效
- [ ] 上传文件无法通过 `/__files/` 直达

```bash

```

## 9. 常见问题

| 现象 | 排查 |
|---|---|
| 登录成功但刷新掉线 | Cookie 是否被浏览器拦截；`NODE_ENV=production` 下没 HTTPS 却加了 Secure；代理头/trust proxy |
| 所有写请求 403 | CSRF Cookie/头是否都有；跨域；前端是否用 `api.js` |
| 上传 413 | Nginx `client_max_body_size` 与 multer 限制 |
| 上传 422 | 文件真实类型不是 PDF/JPG/PNG |
| 下载 404 | 是否登录、是否同校、是否 approved（或本人） |
| 管理端 401 | 是否带着 `campus_admin_sid`；用户 Cookie 不能进后台 |
| TOTP 总失败 | 设备时钟不准；验证码已过期；同一码重放 |
| 扫码无反应 | 是否用腾讯身份验证器；otpauth URL 的 issuer/label |
| 管理员忘记动态码 | 用恢复码；没有恢复码就重新 seed 管理员（会覆盖账号） |
| Docker 改代码不生效 | 静态文件挂载即时生效；后端需 `docker compose up --build` 或重启容器 |

## 10. 生产安全提醒

- 替换所有示例密钥与默认密码；
- `.env` 不进 Git、不进发布包、权限 600；
- Nginx 只暴露 80/443，Node/MySQL 只监听本机；
- 定期备份并演练恢复；
- 管理员恢复码离线保存，不放聊天记录；
- 不要把上传目录放进 web 根目录；
- 这是课程项目，上线前请让有经验的工程师做安全评审。
