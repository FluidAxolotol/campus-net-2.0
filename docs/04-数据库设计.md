# 04 · 数据库设计

数据库：MySQL 8.0，字符集 `utf8mb4`，排序规则 `utf8mb4_0900_ai_ci`，时区固定 UTC。
完整 DDL：[`server/sql/001_init.sql`](../server/sql/001_init.sql)。

## 1. 设计原则

1. **学校是根节点**：所有业务表带 `school_id`；
2. **组合外键**：能保证“内容和用户/文件/版块属于同一学校”的地方就用组合外键；
3. **会话不存原始 sid**：只存 `sha256(sid)`；
4. **软删除优先**：帖子用 `status='deleted'`，保留审计；
5. **状态用 ENUM**：状态机有限，ENUM 能在数据库层挡住非法值；
6. **索引服务于真实查询**：`(school_id, status, created_at)` 是列表主索引。

## 2. 表总览

| 表 | 作用 | 是否带 school_id |

| `admin_recovery_codes` | 管理员恢复码（哈希） | 否 |
| `users` | 学生 | 是 |
| `user_sessions` | 学生会话 | 间接（user_id） |
| `admin_sessions` | 管理员会话 | 间接（currentSchoolId 在 data） |
| `apps` | 工具/办事入口 | 是 |
| `files` | 文件元数据 | 是 |
| `exams` | 真题 | 是 |
| `boards` | 社区版块 | 是 |
| `posts` | 帖子 | 是 |
| `post_likes` | 点赞 | 是 |

## 3. 核心表字段

### 3.1 schools

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INT UNSIGNED PK | 学校 id |
| name | VARCHAR(80) | 名称 |
| code | VARCHAR(32) UNIQUE | 短代码，如 sysu |
| email_domain | VARCHAR(120) | 注册邮箱后缀 |
| status | ENUM('active','disabled') | 停用后学生/管理员不能操作 |
| created_at | DATETIME(3) | UTC |

### 3.2 users

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT UNSIGNED PK | |
| school_id | INT UNSIGNED FK | 学校 |
| student_no | VARCHAR(32) | 同校唯一 |
| email | VARCHAR(160) | 全局唯一 |
| display_name | VARCHAR(40) | 昵称 |
| password_hash | VARCHAR(255) | scrypt 格式 |
| degree | VARCHAR(10) | 本科/硕士/博士 |
| enroll_year | SMALLINT UNSIGNED | 入学年份 |
| college / bio | VARCHAR | 个人资料 |
| status | ENUM('pending','active','rejected','disabled') | 注册审核状态 |
| reject_reason | VARCHAR(200) | 驳回原因 |
| failed_login_attempts | TINYINT UNSIGNED | 连续密码错误次数 |
| locked_until | DATETIME(3) | 锁定截止时间 |
| reviewed_by / reviewed_at | 管理员审核 | |
| created_at / updated_at | UTC |

关键索引：

- `UNIQUE(email)`；
- `UNIQUE(school_id, student_no)`；
- `UNIQUE(id, school_id)`：供组合外键引用；
- `(school_id, status, created_at)`：后台审核列表。

状态机：

```text
pending ──通过──► active ──停用──► disabled
   └────驳回────► rejected          └──启用──► active
```

### 3.3 admins

| 字段 | 说明 |
|---|---|
| username | 唯一登录名 |
| password_hash | scrypt |
| totp_secret_encrypted | AES-256-GCM 加密的 Base32 密钥 |
| totp_confirmed | 是否已完成绑定 |
| must_change_password | 首次登录/恢复后强制改密 |
| last_totp_step | 防重放；上一次成功的时间步 |
| failed_login_attempts / locked_until | 登录锁定 |
| status | active/disabled |

管理员不挂 `school_id`：登录成功后把所选学校写入 `admin_sessions.data.currentSchoolId`。

### 3.4 会话表

`user_sessions`：

| 字段 | 说明 |
|---|---|
| id CHAR(64) PK | `sha256(原始 sid)` |
| user_id | 所属学生 |
| data JSON | express-session 序列化数据 |
| expires_at | 过期时间 |
| last_seen_at | 最近活跃时间 |

`admin_sessions` 把 `user_id` 换成 `admin_id`，`data` 里有 `stage` 与 `currentSchoolId`。

索引：`expires_at`、`user_id/admin_id`；每小时任务删除过期行。

### 3.5 apps

| 字段 | 说明 |
|---|---|
| school_id | 归属学校 |
| title / category / summary / icon | 展示 |
| steps JSON | `[{title,hint}]` |
| views | 浏览量 |
| status | active/hidden |

### 3.6 files / exams

`files`：

| 字段 | 说明 |
|---|---|
| school_id / uploader_id | 归属与上传者 |
| storage_key | `UUID.pdf/jpg/png`，物理文件名 |
| original_name | 原始文件名（只展示/下发） |
| mime_type / size_bytes / sha256 | 类型、大小、校验 |
| UNIQUE(id, school_id) | 供组合外键引用 |

`exams`：

| 字段 | 说明 |
|---|---|
| school_id / file_id / uploader_id | 归属、原件、上传者 |
| title / subject / college / semester / exam_type / has_answer | 元数据 |
| status | pending/approved/rejected |
| review_note / reviewed_by / reviewed_at | 审核信息 |
| download_count | 下载计数 |

组合外键：

- `(file_id, school_id) → files(id, school_id)`；
- `(uploader_id, school_id) → users(id, school_id)`。

这样不会出现“真题属于 A 校，但原件属于 B 校”。

### 3.7 boards / posts / post_likes

`boards`：`(school_id, code)` 唯一，每校一套版块。

`posts`：

- `(board_id, school_id) → boards(id, school_id)`；
- `(author_id, school_id) → users(id, school_id)`；
- `like_count` 是冗余计数，事务内与 `post_likes` 同步；
- `status`：published/hidden/deleted。

`post_likes` 主键 `(post_id, user_id)`，同一用户对同一帖子只能点一次；点赞切换在事务中锁帖子行。

### 3.8 qa_threads

`(exam_id, school_id) → exams(id, school_id)`；`(user_id, school_id) → users(id, school_id)`。
问题是用户输入，回答由后端规则生成，前端用 `textContent` 渲染。

### 3.9 corrections / audit_logs / password_reset_requests

- `corrections`：target_type='app'，target_id，content，status（open/resolved/ignored），处理人/时间。
- `audit_logs`：school_id，actor_type（admin/user/system），actor_id，action，target，detail JSON，ip，created_at。只写关键操作，不记录秘密。
- `password_reset_requests`：school_id，user_id，note，status（open/done/ignored），处理人/时间。

## 4. 学校隔离的三层防线

1. **应用层**：每个请求的学校从会话取（学生 `req.user.schoolId` / 管理员 `req.session.currentSchoolId`）；
2. **SQL 层**：每条读写 SQL 都带 `school_id = ?`；跨校影响 0 行 → 404；
3. **数据库层**：组合外键保证关联对象同校，即使应用层漏写也插不进去。

## 5. 索引与查询

典型列表查询：

```sql
SELECT ...
  FROM exams e
 WHERE e.school_id = ? AND e.status = 'approved'
 ORDER BY e.created_at DESC, e.id DESC
 LIMIT 10 OFFSET 0;
```

对应索引 `(school_id, status, created_at, id)`。
复合索引顺序原则：等值列在前（school_id/status），排序列在后（created_at/id）。

后台审核列表按 `school_id + status + created_at` 排序/筛选，命中同族索引。

## 6. 事务边界

| 操作 | 事务内容 |
|---|---|
| 上传真题 | INSERT files + INSERT exams；失败删文件 |
| 审核真题 | SELECT ... FOR UPDATE + UPDATE exams + INSERT audit |
| 点赞 | SELECT post FOR UPDATE + INSERT/DELETE like + UPDATE like_count |
| 审核注册 | UPDATE users + INSERT audit |
| 停用用户 | UPDATE users + DELETE user_sessions + INSERT audit |
| 管理员首次绑定 | UPDATE admins + DELETE/INSERT recovery codes + INSERT audit |
| 管理员使用恢复码 | UPDATE recovery used + UPDATE admins + INSERT audit |
| 重置用户密码 | UPDATE users + DELETE user_sessions + UPDATE request + INSERT audit |

事务要短，异常必须 ROLLBACK，连接必须 release。

## 7. 备份与恢复

- 数据库 + uploads 必须一起备份；
- `mysqldump --single-transaction` 保证 InnoDB 一致性且不锁表；
- 恢复演练：导入临时库 + 解压文件 + 核对表/文件数量；
- 发布前、迁移前手动备份；生产每日 cron。

## 8. 迁移

`server/scripts/migrate.js`：

1. 建 `schema_migrations`；
2. 按文件名排序读 `server/sql/*.sql`；
3. 已执行跳过，未执行执行并记录；
4. 可重复运行，不重复建表。

新增结构变更时添加 `002_xxx.sql`，不要改已执行的 `001`。
